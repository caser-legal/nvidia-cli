## SwiftUI Lessons Learned (Critical - Read Before iOS Work)

### Background Images - MUST USE GeometryReader
```swift
**Image Expansion on Scroll**

**Bad:**
```swift
ZStack {
    Image(“background”).resizable().aspectRatio(contentMode: .fill).ignoresSafeArea()
    ScrollView { … }
}
```

**Good:**
```swift
GeometryReader { geo in
    ZStack {
        Image(“background”)
            .resizable()
            .aspectRatio(contentMode: .fill)
            .frame(width: geo.size.width, height: geo.size.height)
            .clipped()
        // Other content
    }
}
.ignoresSafeArea()
```

**Dark Mode + Custom Background Images**

- `.ultraThinMaterial` adapts to background color
- Light background image = light material even in dark mode
- **FIX:** Layer image UNDER semi-transparent gradient overlay to preserve dark tones

**Buttons - Make Entire Row Tappable**

**Bad:**
```swift
Button { action() } label: {
    HStack { Label(“Action”, systemImage: “star”); Spacer() }
}
```

**Good:**
```swift
Button { action() } label: {
    HStack { Label(“Action”, systemImage: “star”); Spacer() }
}
```
        Content Shape
```swift
.contentShape(Rectangle())
}
.buttonStyle(.plain)
```

Sheet Race Conditions
```swift
// ❌ BAD - Race condition on first tap
@State var selectedItem: Item?
@State var showSheet = false
Button { selectedItem = item; showSheet = true }
.sheet(isPresented: $showSheet) { DetailView(item: selectedItem) } // nil!

// ✅ GOOD - No race condition
@State var selectedItem: Item?
Button { selectedItem = item }
.sheet(item: $selectedItem) { item in DetailView(item: item) }
```

List vs ScrollView Styling
- `List` has its own background and styling
- For custom glass card styling, use `ScrollView` with custom components
- If using List with custom background: `.scrollContentBackground(.hidden)`

Font Files in Xcode
- Font files MUST be added to Xcode project manually (drag into project)
- Add to Info.plist under `UIAppFonts` array
- Font won’t load until in “Copy Bundle Resources” build phase

## File Editing Rules (Mandatory)

### Never use `sed` for multi-line Swift edits
- `sed` corrupts files with complex multi-line patterns
- Swift syntax is too complex for `sed`

### Always use `file_write` for Swift changes
1. Read the full file with `file_read`
2. Make changes in memory
3. Write the complete file with `file_write`

### Never manually edit Xcode project.pbxproj
- The format is complex, and manual edits corrupt the file
- Use Xcode GUI or the xcodeproj Ruby gem
- If corrupted: `git checkout — *.xcodeproj/project.pbxproj`

### One Change at a Time
1. Make one change
2. Build and verify
3. Test the actual behavior
4. Only then proceed to the next change
